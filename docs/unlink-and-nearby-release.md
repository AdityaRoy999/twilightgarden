# Connection lifecycle, nearby search, and viewport UI

Unlinking previously attempted browser-side deletes. RLS allowed removal of only the sender’s messages, leaving the partner’s messages to block relationship deletion. Storage objects were never removed.

The couple-action endpoint verifies the caller’s JWT, checks membership in a service-only database operation, atomically removes the conversation and relationship, and deletes all chat-media objects under the relationship’s prefix using the Storage API. Nested files are handled. A service-only cleanup queue retries failures and recent completed jobs via the existing reminder schedule, covering uploads already in flight. A 202 response clearly reports queued media cleanup; membership and database access are already removed. Normal completion returns only after Storage deletion. Client caches, drafts, pending sends and queued outbox entries are cleared; account-scoped Realtime events notify both parties after deletion. Chat recovery appears only for active relationships. Personal health logs and account encryption identities are retained; those identity backups cannot restore deleted message rows or attachments. Files saved outside the app and provider backup retention are outside this operation.

Code generation and joining use transactional server functions. Joining an invalid code preserves a pending code; successful joining clears the joining account’s old pending code. Actor account locks prevent concurrent duplicate connections. Pending codes expire after 24 hours, and the shared connection screen can replace an expired code. Direct authenticated deletion of an active relationship is blocked so it cannot bypass media cleanup.

The shared illustrated connection screen is used by chat and connection-dependent partner pages and games. Individual health tracking does not require a partner. The navigation bar uses 14px outer / 8px selection corners, with genuinely transparent paint when Solid Navbar Background is off. Notifications render in a MotionPortal with fixed positioning, outside route transforms; keyboard close and outside dismissal are supported.

Nearby search retains the area coordinates returned by the backend, uses them for distances/map/routing, and falls back from Photon’s POI index to an Overpass query for pharmacy and chemist objects. Service errors are displayed as errors rather than a false empty result. Public endpoints are best effort and are not an inventory service. PHOTON_BASE_URL and OVERPASS_URL can be configured as backend secrets for hosted instances; no Google API key is required.

For a small EC2 deployment, limit the dataset to a supported city/region and use a regional OSM POI database plus a spatial index for nearby pharmacy search. A full worldwide Photon/Nominatim/Overpass installation is not a tiny-instance workload. Map tiles are a separate service: Leaflet is the renderer, while Protomaps PMTiles can be served from S3/CloudFront. Neither provides live pad stock; that needs retailer inventory feeds.

Validation: 22 live checks using three disposable accounts cover role pairing, invalid/self joins, pending code preservation, unauthorized/spoofed unlink denial, privileged RPC denial, deletion of both senders’ messages and nested attachments, stale signed URL failure, game/invitation deletion, both account Realtime events, idempotent retries, clean relinking and pharmacy results for coordinates and Salt Lake, Kolkata. All fixtures were removed. Unit regressions cover connection UI, provider fallback, notification portals and identity recovery. Browser previews verify the disconnected layout and transparent navbar.

The iOS bundle includes camera/microphone usage descriptions and WebRTC capture. Sideloading permits foreground voice/video calls subject to permission, encryption setup, connectivity and TURN. This build still does not implement APNs/CallKit background incoming calls; a locked or closed app cannot be promised to ring. Physical iPhone two-party call testing was not performed by this automation.
